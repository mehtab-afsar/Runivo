# Audit, November 2026: findings and status

Three read-only audits (security, bugs and reliability, dead and duplicate code) were run over the mobile app, `packages/shared`, `supabase/` and the web app, then the findings were worked through in priority order. IDs below are the audit's. Use [SECURITY_CHECKLIST.md](SECURITY_CHECKLIST.md) to re-check before each release.

Status key: **Fixed** = changed and verified by a test or typecheck here. **Deploy** = fixed in a migration or edge function that must be deployed before it protects anything. **Open** = not done.

All Supabase findings came from reading migrations, not from the live project. Verify with `supabase/tests/audit_function_privileges.sql` after deploying.

## Security

| ID | Finding | Status |
|---|---|---|
| C1 | Server-only `SECURITY DEFINER` functions (`steal_territory_portion`, `claim_unclaimed_area`, `increment_run_stats`, `diagnose_pace_ledger`, and others) executable by any client, because re-creating a function resets its grants to Postgres's default | **Deploy** `20261115000010` (tested on a scratch DB: fails before, passes after). A schema-level default-privilege change does *not* work, so each new privileged function still needs its own `REVOKE`. |
| H1 | Run scoring trusted a client-written trace | **Partly fixed, Deploy.** `process-run-territory` now rejects a request that disagrees with the stored run (sport, duration, time window), caps points at 40,000, and pays nothing for runs flagged with mock location (Android reports it; iOS has no equivalent in expo-location). **Still open:** the trace is still client-supplied, so a determined cheater who fabricates both the row and the trace is not stopped. That needs device attestation (App Attest / Play Integrity). |
| H2 | Magic-link `token_hash` login was not device-bound (login CSRF / session swap) | **Fixed** (PKCE `code` only; ignored when already signed in; 6 tests). |
| H3 | Direct reads of `territory_polygons` ignored "hide my zones"; `get_city_rank` was a location oracle | **Deploy** `20261115000011`. The `get_city_rank` function and the policy need PostGIS and were not run here. |
| H4 | Missions and leaderboards trust raw client-written `runs` and `nutrition_logs` rows | **Missions fixed, Deploy** `20261115000018`: distance missions count only server-verified distance (`supabase/tests/mission_verified_distance.test.sql`). **Open:** leaderboard distance is still the recorded distance (it already skips integrity-flagged and excluded runs; it is rank, not money), and the nutrition mission reads client-written logs (the feature is off). |
| H5 | `feed`/`stories` buckets are public, listable, and keep photo EXIF (home coordinates) | **Partly fixed, Deploy** `20261115000019`: the buckets can no longer be listed by anyone (owner-only), so the file names cannot be harvested (`storage_listing.test.sql`). Photos are re-encoded at pick time (quality 0.75), which drops EXIF on the app's picker path; **verify with `exiftool` on an uploaded file**. **Open:** a photo on a private or followers-only activity is still readable by anyone who has its URL. Closing that needs private buckets, signed URLs and a per-viewer access rule, which changes how every photo is displayed and needs a device to test. |
| M1 | Clients could set `device_connections.metadata.provider_user_id`, which the webhook trusts for routing | **Deploy** `20261115000011` (trigger; tested). |
| M2 | Anyone could insert `curated` events with arbitrary links while subscriptions are off; `openURL` had no scheme check | **Deploy** `20261115000011` (policy dropped, http(s) constraint, tested). **Fixed** client-side (`safeHttpUrl`, tested). |
| M3 | `handle_referral` callable by anyone with any ids | **Deploy** `20261115000011` (dropped; nothing called it). |
| M4 | Session tokens stored unencrypted in AsyncStorage | **Fixed** (needs a new native build for `expo-secure-store`'s Keychain access; verify on a device that sign-in survives a restart and that an upgrade from an older build stays signed in). AES-256 key in the Keychain, session encrypted in AsyncStorage (`sessionCrypto.ts`, 5 tests; `secureSessionStorage.ts`). Old plain sessions are upgraded in place. |
| M5 | Sign-out left GPS buffer, checkpoints, weight log, queued writes, cached plan, RevenueCat identity | **Fixed** (`signOut`, `clearLocalUserData`, `logOutRevenueCat`). |
| M6 | Account deletion missed nested storage files, the Apple token, provider links | **Partly fixed, Deploy.** Storage is now walked recursively (4 tests). **Open:** Sign in with Apple token revocation (needs your Apple key and a fresh authorization code from the app) and Garmin deauthorisation. PostHog data is now deleted with the account (`posthogDelete.ts`; needs `POSTHOG_PROJECT_ID` and `POSTHOG_PERSONAL_API_KEY` secrets). |
| M7 | `profiles_public` ignores visibility; `feed_posts` stat columns are client-writable | **Open.** |
| M8 | `diagnose_pace_ledger` callable by clients | **Deploy** (covered by C1). |
| M9 | No analytics consent | **Partly fixed.** Settings → Privacy and data has a "Usage analytics" switch that stops PostHog at once and is remembered, and the privacy policy discloses it. **Open, your decision:** analytics is still on by default (disclosed, with an opt-out). Strict opt-in (off until the runner agrees) is the stricter choice, and the one EU rules lean towards. |
| M10 | Hosted Auth settings (captcha, email confirmation, rate limits) | **Open.** Dashboard only; cannot be done from the repo. |
| M11 to M13 | Speed ceilings disagree; AI-coach cost cap race; region gate trusts client coordinates | **Open.** |
| P1-20 | One push token could belong to two accounts, so notifications reached the wrong person | **Deploy** `20261115000012` (trigger plus one-time cleanup; tested). |

## Structure

**Started, not finished.** `eslint.config.mjs` now warns on every import from one feature into another (83 today, `npm run lint | grep "Cross-feature"`), so the coupling is a countable list. One real move was made as the template: `safetyService` and `promptReport` went from `features/social` to `src/shared`, because clubs, events, profile and settings all use them. The rest of the proposed target (a `domain/` layer, `shared/feedback`, `navigation/` into `app/`, splitting `sync.ts`) is **not done**: moving hundreds of files while other work is in flight in the same tree guarantees conflicts. Do it in a quiet window, one step per PR, working the warning count down.

Added this round: magic-link handling, the run-consistency checks, the storage walk, `safeHttpUrl`, pace rounding, and a database test for function privileges. **Still missing:** tests for `useActiveRun`, `locationTask`, crash recovery, sync retry behaviour and `store.native`; CI runs none of the 28 SQL tests, `scripts/db-integration-tests.ts`, a Deno check of the edge functions, or `expo-doctor`; vitest does not pick up `.test.tsx`; and `@typescript-eslint/no-floating-promises` is not enabled (it would have caught P1-1).
